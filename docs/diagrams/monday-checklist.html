five numbers to check monday morning
if you look at nothing else, look at these · each one is a user-facing problem before it is an alert
1
max children reachedfpm status page / exporter counter
healthy: 0 · rising = pool ceiling hit, requests queuing while CPU may be idle
2
listen queuefpm status page · the queue PHP never sees
healthy: 0 · any sustained value = users already waiting before PHP runs
3
opcache hit rate + wasted %opcache_get_status() / our /metrics route
healthy: > 99% hit, < 5% wasted · full + wasted = restart storms, compile tax per request
4
memory per worker (RSS)ps / htop, measured warm under load
the unit behind max_children = RAM ÷ this · growing = leak, recycling saves you (pm.max_requests)
5
oldest job agequeue metrics · not queue depth
healthy: within your SLA · depth lies, 10k fast jobs is fine, 10 slow ones may not be
everything on this list is one command in the demo repo · github.com/dragoonis/scaling-php
