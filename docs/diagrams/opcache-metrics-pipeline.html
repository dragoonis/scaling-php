OPcache Exporter Pipeline

How compiled-script stats leave each PHP runtime and reach the OPcache dashboard

Where the stats live

  • • OPcache keeps compiled PHP bytecode in shared memory
  • • One SHM segment per master process: FPM, classic, worker each have their own
  • • Only PHP itself can read it, via opcache_get_status()
  • • So the exporter must ask PHP, it cannot scrape from outside

The agent

  • • public/agent-pull.php runs inside each runtime
  • • Dumps opcache_get_status() + configuration as JSON
  • • Pull model: the collector calls the agent over plain HTTP :80
  • • Same file works under FPM, FrankenPHP and Octane

The collector + UI

  • • GoMetric opcache-dashboard polls all three hosts every 5s
  • • make up-opcache-dashboard, then open :42042
  • • Shows hit rate, memory usage, wasted memory, cached keys
  • • Can also push to statsd (unused in this demo)
