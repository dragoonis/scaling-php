FrankenPHP Worker Tuning

The knobs that matter, with the values this demo runs on an 8-core machine

Sizing

  • • Start at workers = 2 x CPU cores, measure, adjust
  • • More io-wait (db, http calls) supports more workers per core
  • • Each worker holds a booted app in memory, watch RSS
  • • num_threads slightly above workers for non-PHP requests

Lifecycle

  • • --max-requests recycles workers, leaks cannot accumulate
  • • octane:reload for deploys, zero dropped requests
  • • The app boots once, state persists between requests
  • • So reset globals/statics carefully (Octane docs cover it)

Observability

  • • admin :2019 + metrics option exposes frankenphp_* metrics
  • • busy_threads vs total_threads = utilization
  • • queue_depth is the saturation alarm
  • • per-worker request_count shows recycling live
