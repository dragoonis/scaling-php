horizon balances. the autoscaler sizes.
they answer different questions, and they are not enemies
Laravel Horizon
"how do I split my workers across queues?"
  • balances a worker pool across queues by load
  • the pool size itself: maxProcesses, still a number you pick
  • beautiful dashboard, metrics, failed-job UI
  • redis only
SLA autoscaling
"how many workers should exist at all?"
  • derives the count from an SLA + Little's Law, every 5s
  • capped by measured host CPU/RAM, not a guess
  • failure fuse: an outage is not load
  • any driver: redis, database, SQS
the gap in both worlds was never balancing, it was that someone still picks the number. stop picking the number.
measured in this repo: 3,000-job burst sized itself 1 → 16 workers and back, zero config edits, zero lost jobs
